# Plan V1 avec Engine — proposition du 21 octobre 2026

**Cible : créer, valider, générer, corriger, sauvegarder et rouvrir un exercice canonique dans Admin Staging, puis démontrer son exécution dans NovLearn avec le même Engine.** Le pilote éditorial n'est reçu qu'après ce parcours. La publication Production, statistiques/utilisateurs Production, nouvelles courbes 0.2.0 et mobile restent des lots distincts ; le CDC complet n'est pas déclaré terminé. [Constats et preuves](audit-v1-2026-10-21.md).

Ce plan n'autorise aucune implémentation. Estimation indicative après accès et choix d'hôte : étapes 1–5, environ 4–8 jours de travail ; adaptation consommateurs étape 6, environ 3–7 jours supplémentaires selon les parcours retenus. Ce sont des fourchettes de planification, pas des mesures ni une date de livraison. Ne pas paralléliser les changements de contrat et leur adoption sans point de coordination.

## Bornes à conserver

Worker : 5 s par opération incluant la file, 384 Mio maximum, heap 128 Mio, swap nul, 64 pids maximum, entrée 1 Mio/sortie 2 Mio/stderr 64 Kio ; host Admin 1 actif/4 en attente. API Admin : corps 256 Kio ; aperçu/correction 20 s, tests 120 s ; transport local 10 s. Tests : 1–5 seeds distinctes, 16 cas, 8 questions maximum. Snapshots : 10 min, 2/Admin, 32/processus, 512 Kio ; travaux 1/Admin et 2/processus. Conserver toutes les autres limites existantes, notamment signature/publication ; ce tableau ne les remplace pas. Les protections locales qui refusent un domaine ou un profil distant se modifient uniquement dans une étape autorisée et testée, jamais par une variable de contournement.

## Parcours de réception complet à exécuter après autorisation

1. **Préparer** un espace Staging d'essai autorisé et un exercice identifié ; relever commit, hash d'archive, identité du pipeline, hôte et origine. Ne pas employer de données élèves Production. Sauvegarde adaptée avant toute modification distante ; pas de suppression automatique après essai.
2. **Se connecter** par Supabase Staging avec le compte Admin ; vérifier son environnement affiché, déconnexion/reconnexion, refus non connecté et non-admin. Contrôler côté serveur un rôle frais ; éprouver révocation/expiration sur compte d'essai, sans modifier les délais.
3. **Composer** dans le builder un exercice avec variable entière, variable calculée dépendante, contrainte, texte, expression et question MathLive ; ajouter un QCM dans un second cas. Tester dépendance inconnue/cycle et correction du diagnostic. Aucun JSON manuel ni calcul applicatif parallèle.
4. **Valider et générer** via Engine : seeds 0 et 42 puis rejeu ; vérifier contraintes, réponse correcte, équivalente autorisée, incorrecte et format invalide. Vérifier une génération impossible ; aucune sortie partielle présentée comme complète. Inspecter l'attendu seulement avec l'action privée Admin. Les tests temporaires ne doivent pas exiger de clé de signature.
5. **Sauvegarder** le brouillon validé, relever exercice/version/empreinte ; quitter, se reconnecter et rouvrir. Définition canonique, métadonnées, ordre, politiques, contraintes et références conservés. Régénérer et comparer avec le contenu relu ; les nouveaux IDs d'instance sont explicitement distincts. Deux onglets : sauvegarde concurrente refusée en 409, saisie du perdant conservée.
6. **Contrôler le réseau** : projection élève sans attendus/politiques privées ; aucune instance officielle acceptée du navigateur ; aperçu d'un autre compte refusé, expiration/redémarrage produit 410. Vérifier les accès directs Supabase et RPC en plus des routes Admin, sur fixtures autorisées.
7. **Ouvrir dans NovLearn Staging** la même révision canonique par le chemin serveur reçu. Pour une réception fidèle aux règles « published uniquement », utiliser d'abord une cible isolée et le mécanisme de publication approuvé ; ne pas rendre un brouillon accessible aux élèves. Vérifier rendu, soumission, correction Engine, reprise de tentative et identité de version. Rejouer DS/duel si ces parcours sont annoncés compatibles. Toute différence constitue un échec de compatibilité, pas une conversion à faire dans Admin.
8. **Consigner** résultat humain, résultats techniques, limites et données d'essai créées ; aucun test Production ou publication réelle déduit de ce parcours. La publication réelle sera un lot distinct : reçu courant, relecture, mapping/references, préconditions sur deux bases, transfert limité aux deux tables approuvées, vérification, journal et rollback.

## Décisions et autorisations indispensables seulement

- Valider l'écart à D13 : hôte Linux commun recommandé, ou maintien de Vercel avec service Linux séparé. Choisir responsable d'exploitation, région, domaine, budget et niveau de disponibilité ; aucun achat ni installation dans cet audit. Les sources officielles et différences de coûts sont dans le rapport.
- Autoriser séparément les corrections du dépôt NovLearn et, si nécessaire, d'Engine ; le plan privilégie l'archive actuelle et n'exige pas de nouveau cœur mathématique. Ne pas redemander le modèle à deux tables, le périmètre de publication ou la cible Linux déjà décidés.
- Autoriser par cible les futures écritures Staging, migrations, essais persistants et déploiements, après revue de leur delta et sauvegarde. Production reste fermée ; les données pédagogiques seules seront transférables par le mécanisme approuvé.
- Trancher explicitement l'exception de brouillon incomplet si souhaitée (§16 du CDC). Provisionner une signature uniquement si des rapports/relectures persistants sont requis ; leur absence ne justifie pas de retirer Engine du pilote.
- Pour compléter le seul audit Production : autorisation explicite de lecture des métadonnées du projet `novlearn-prod` ; la tentative de cet audit a été refusée automatiquement. Aucune lecture de secrets ou de données personnelles nécessaire.

L'API mobile future réutilisera identité d'exercice/version, projection publique et contrats de soumission/correction, derrière les autorisations serveur du consommateur. Son framework, son hébergement et le partage éventuel d'un service Engine ne sont pas des décisions préalables à cette V1.
